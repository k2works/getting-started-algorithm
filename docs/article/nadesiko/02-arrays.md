# 第 2 章 配列

## はじめに

配列は、複数の値を順序付きでまとめて扱うデータ構造です。要素をひとつずつ変数に入れる代わりに、配列と繰り返しを組み合わせることで、要素数が変わっても同じアルゴリズムを使えます。

この章では配列の要素を走査して最大値を求め、要素を入れ替えて並びを反転します。さらに、配列を使って基数変換と素数列挙を実装し、素朴な方法から効率を改善する過程をテストで確かめます。

## 2.1 なでしこ3 の配列

配列は `[]` で作成します。要素の番号（インデックス）は `0` から始まり、`配列参照` で指定した位置の値を取得できます。

```nako3
点数一覧 = [72, 85, 91]
最初の点数 = 点数一覧の0を配列参照
点数一覧に88を配列追加
```

`配列追加` は配列の末尾に値を加え、配列自体も変更します。関数に配列を渡す場合も同じ配列を参照するため、関数の中で要素を入れ替えると呼び出し側の配列も変わります。変更を分離したいときは、`配列複製` で配列を複製してから操作します。

配列全体を処理する基本形は、配列の要素数とインデックスを使った繰り返しです。

```nako3
要素数 = 点数一覧の配列要素数
Iを0から(要素数 - 1)まで繰り返す
    点数 = 点数一覧のIを配列参照
    点数を表示
ここまで
```

## 2.2 配列の最大値

空でない数値配列を受け取り、最大の要素を返します。配列が空の場合は先頭要素を取得できないため、この関数は少なくとも 1 要素あることを前提とします。

### Red: 期待する振る舞いを書く

`test/arrays_test.nako3` に、通常の配列、1 要素、同じ値だけの配列をテストします。

```nako3
「最大値」と([172, 153, 192, 140, 165]を配列内最大)と192で検証
「最大値: 1要素」と([42]を配列内最大)と42で検証
「最大値: 同じ値」と([5, 5, 5]を配列内最大)と5で検証
```

まだ `配列内最大` がない状態ではテストを実行できません。関数を実装してテストが通ることを確認します。

### Green: 先頭を暫定の最大値にする

`src/arrays.nako3` に、先頭の値を最大候補として残りを走査する関数を定義します。

```nako3
●(値一覧を)配列内最大
    配列長 = 値一覧の配列要素数
    最大候補 = 値一覧の0を配列参照
    Iを1から(配列長 - 1)まで繰り返す
        値 = 値一覧のIを配列参照
        もし、値 > 最大候補ならば
            最大候補 = 値
        ここまで
    ここまで
    最大候補を戻す
ここまで
```

`最大候補` は「先頭から現在の位置までに見た値の最大値」を保ちます。各要素を一度ずつ調べるため、要素数を `n` とすると時間計算量は O(n)、追加の空間計算量は O(1) です。

## 2.3 配列の要素を反転する

配列の先頭と末尾、その次に内側の要素どうしを交換していくと、配列を反転できます。なでしこ3 の `配列入替` は配列を直接変更するため、戻り値だけでなく元の配列も確認します。

### Red: 変更される配列も確認する

```nako3
奇数配列 = [2, 5, 1, 3, 9, 6, 7]
「奇数要素の反転」と((奇数配列を配列反転)を「,」で配列結合)と「7,6,9,3,1,5,2」で検証
「反転時に元の配列も更新」と(奇数配列を「,」で配列結合)と「7,6,9,3,1,5,2」で検証

偶数配列 = [1, 2, 3, 4]
「偶数要素の反転」と((偶数配列を配列反転)を「,」で配列結合)と「4,3,2,1」で検証
「1要素の反転」と(([42]を配列反転)を「,」で配列結合)と「42」で検証
「空配列の反転」と(([]を配列反転)を「,」で配列結合)と「」で検証
```

テストでは配列そのものではなく、配列を文字列に結合して内容を比べています。配列は同じ要素を持っていても別の配列として比較される場合があるため、要素の内容を比較する形にしています。

### Green: 対称位置の要素を入れ替える

```nako3
●(値一覧を)配列反転
    配列長 = 値一覧の配列要素数
    Iを0から(配列長 - 1)まで繰り返す
        J = 配列長 - I - 1
        もし、I < Jならば
            値一覧のIとJを配列入替
        ここまで
    ここまで
    値一覧を戻す
ここまで
```

`I` と `J` が中央を越えて同じ組を二度交換しないよう、`I < J` のときだけ入れ替えます。ループは配列全体を走査しますが、実際に交換するのはおよそ半分です。時間計算量は O(n)、追加の空間計算量は O(1) です。空配列と 1 要素の配列では交換が起きません。

配列を変更せずに反転したい場合は、元の配列を複製してから `配列反転` を呼び出します。

```nako3
元配列 = [1, 2, 3]
複製配列 = 元配列を配列複製
複製配列を配列反転
```

`配列複製` はここでは外側の配列を複製します。配列の中にさらに配列や辞書がある場合の入れ子要素の共有については、コピーが必要な場面ごとに確認してください。

## 2.4 基数変換

整数を別の基数で表すには、基数で割った余りを下位桁から順に求めます。余りは下位桁から得られるため、新しい桁を文字列の先頭へ追加すると、最後に反転する必要がありません。

この関数は `0` 以上の整数と、2 から 36 までの基数を受け取る前提です。10 以上の桁には `A` から `Z` を使います。

### Red: 2 進数・8 進数・16 進数をテストする

```nako3
「2進数」と(29と2で基数変換)と「11101」で検証
「8進数」と(29と8で基数変換)と「35」で検証
「16進数」と(255と16で基数変換)と「FF」で検証
「0の基数変換」と(0と2で基数変換)と「0」で検証
```

### Green: 余りを桁に変換する

```nako3
●(数値と基数で)基数変換
    もし、数値 = 0ならば
        「0」を戻す
    ここまで
    文字一覧 = 「0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ」を文字列分解
    変換結果 = 「」
    残り = 数値
    残り > 0の間
        余り = 残り % 基数
        文字 = 文字一覧の余りを配列参照
        変換結果 = 「{文字}{変換結果}」
        残り = (残り - 余り) ÷ 基数
    ここまで
    変換結果を戻す
ここまで
```

`残り` が 0 になるまで、余りを桁文字に置き換えて変換結果へ追加します。各反復で値は基数で割られるため、時間計算量は O(logᵣ n) です（`n` は変換する数、`r` は基数）。

## 2.5 素数の列挙と改善

素数候補を割り算で調べる方法を段階的に改善します。比較するため、各関数は素数の一覧ではなく、実行した剰余演算（`%`）の回数を返します。演算回数を測ることで、最適化の効果を同じ入力で比べられます。

### Red: 演算回数を固定してテストする

```nako3
「素数 v1 の剰余演算回数」と(1000まで素数除算回数一)と78022で検証
「素数 v2 の剰余演算回数」と(1000まで素数除算回数二)と14622で検証
「素数 v3 の剰余演算回数」と(1000まで素数除算回数三)と1804で検証
```

### Green: 第 1 版 — すべての整数で割る

```nako3
●(上限まで)素数除算回数一
    演算回数 = 0
    Nを2から上限まで繰り返す
        素数候補 = はい
        Dを2から(N - 1)まで繰り返す
            もし、素数候補ならば
                演算回数 = 演算回数 + 1
                もし、N % D = 0ならば
                    素数候補 = いいえ
                ここまで
            ここまで
        ここまで
    ここまで
    演算回数を戻す
ここまで
```

各 `N` を 2 から `N - 1` までの整数で割ります。割り切れた時点で `素数候補` を `いいえ` にし、それ以上の剰余演算を行わないようにしています。

### Refactor: 奇数だけを調べ、見つけた素数を使う

2 より大きい偶数は素数ではないため、候補から除外できます。また、合成数は素数で割り切れるため、これまでに見つけた素数だけで調べられます。

```nako3
●(上限まで)素数除算回数二
    演算回数 = 0
    素数一覧 = [2]
    Nを3から上限まで繰り返す
        もし、N % 2 = 1ならば
            素数候補 = はい
            配列長 = 素数一覧の配列要素数
            J = 1
            J < 配列長かつ素数候補の間
                素数 = 素数一覧のJを配列参照
                演算回数 = 演算回数 + 1
                もし、N % 素数 = 0ならば
                    素数候補 = いいえ
                ここまで
                J = J + 1
            ここまで
            もし、素数候補ならば
                素数一覧にNを配列追加
            ここまで
        ここまで
    ここまで
    演算回数を戻す
ここまで
```

`素数一覧` のインデックス 0 には 2 が入っています。候補 `N` は奇数だけなので、2 で割る必要はなく、インデックス 1 から調べています。見つけた素数を配列に追加し、次の候補で再利用します。

### Refactor: 平方根以下の素数だけを調べる

合成数 `N` は、少なくとも一つの約数が √N 以下です。そのため、√N を超える素数で割る必要はありません。積 `素数 × 素数` と `N` を比べ、平方根以下の範囲だけ剰余演算を行います。

```nako3
●(上限まで)素数除算回数三
    演算回数 = 0
    素数一覧 = [2, 3]
    Nを5から上限まで繰り返す
        もし、N % 2 = 1ならば
            素数候補 = はい
            配列長 = 素数一覧の配列要素数
            J = 1
            素数 = 素数一覧のJを配列参照
            J < 配列長かつ素数候補かつ(素数 × 素数 <= N)の間
                演算回数 = 演算回数 + 1
                もし、N % 素数 = 0ならば
                    素数候補 = いいえ
                ここまで
                J = J + 1
                もし、J < 配列長ならば
                    素数 = 素数一覧のJを配列参照
                ここまで
            ここまで
            もし、素数候補ならば
                素数一覧にNを配列追加
            ここまで
        ここまで
    ここまで
    演算回数を戻す
ここまで
```

この版では、平方根を計算せずに `素数 × 素数 <= N` を条件として使います。3 つの関数は剰余演算回数だけを計測しているため、ループ制御や比較にかかる処理時間全体を直接表す値ではありません。

### 1000 以下での比較

| 版 | 改善 | 剰余演算回数 |
|----|------|-------------:|
| 第 1 版 | 2 から `N - 1` までの整数を試す | 78,022 |
| 第 2 版 | 偶数を除き、見つけた素数を使う | 14,622 |
| 第 3 版 | さらに平方根以下の素数だけを試す | 1,804 |

上限が大きくなるほど、割る候補を減らす効果が大きくなります。ここで数えているのは剰余演算だけなので、実行時間や他の命令の回数と混同しないようにします。

## 2.6 コピーと変更の確認

`配列追加` や `配列入替` のような更新命令は、渡した配列そのものを変更します。変更の影響を局所化したいときはコピーを使います。次のテストでは、複製側に要素を追加しても、元配列の内容は変わらないことを確認します。

```nako3
元配列 = [1, 2, 3]
複製配列 = 元配列を配列複製
複製配列に4を配列追加
「複製への追加が元配列に影響しない」と(元配列を「,」で配列結合)と「1,2,3」で検証
「複製した配列への追加」と(複製配列を「,」で配列結合)と「1,2,3,4」で検証
```

## 2.7 テストの実行と計算量

実装は `src/arrays.nako3`、テストは `test/arrays_test.nako3` にあります。プロジェクトのルートから次のコマンドを実行すると、lint・整形チェック・全テストを確認できます。

```bash
cd apps/nadesiko
make check
```

| 処理 | 時間計算量 | 追加の空間計算量 | 配列への変更 |
|------|-----------:|-----------------:|-------------|
| 最大値 | O(n) | O(1) | なし |
| 配列反転 | O(n) | O(1) | あり |
| 基数変換 | O(logᵣ n) | O(logᵣ n) | なし |
| 素数列挙 v1 | O(n²)（上界） | O(1) | 内部の候補判定のみ |
| 素数列挙 v2 | O(n²)（上界） | O(π(n)) | 内部の素数配列を更新 |
| 素数列挙 v3 | O(n√n)（上界） | O(π(n)) | 内部の素数配列を更新 |

`n` は配列の要素数、または素数列挙の上限です。`π(n)` は `n` 以下の素数の個数です。v2・v3 の比較では、剰余演算回数をテストで固定し、アルゴリズムの変更による違いを確かめました。

## まとめ

この章では、配列のインデックスによる走査、配列を直接変更する操作、基数変換、素数を調べる方法の改善を学びました。配列を関数へ渡すときは、戻り値だけでなく元の配列が変更されるかもテストで確かめることが重要です。

次章では、線形探索・二分探索・ハッシュ法を取り上げ、配列や別のデータ構造から目的の値を見つける方法を学びます。
