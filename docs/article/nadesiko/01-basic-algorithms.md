# 第 1 章 基本的なアルゴリズム

## はじめに

アルゴリズムとは、問題を解決するための明確な手順です。この章では、3 値の最大値と中央値、条件による分岐、繰り返し処理、多重ループを題材に、TDD で基本的なアルゴリズムを実装します。

前作の「テスト駆動開発から始める なでしこ3 入門」で学んだテストの書き方と `ASSERT等` を使います。テストを先に書き、失敗することを確かめてから最小限の実装を加え、最後に読みやすさを整えます。

## 1.1 アルゴリズムとは

コンピュータは、入力を受け取り、決められた手順を実行し、結果を出力します。その手順がアルゴリズムです。アルゴリズムをテストするときは、通常の入力だけでなく、同じ値が並ぶ場合や境界となる入力も確認します。

なでしこ3 の関数は、`●(Nを)関数名` のように定義します。呼び出すときも `Nを関数名` と書くため、日本語の文として引数と処理の関係を読み取れます。

## 1.2 3 値の最大値

3 つの数から最大の値を返す関数を作ります。引数の順序が違う場合や、最大値が複数ある場合もテストします。

### Red: テストを先に書く

`test/basic_algorithms_test.nako3` に、まず期待する振る舞いを記述します。

```nako3
3と(3と2と1で三値最大)がASSERT等
3と(3と2と2で三値最大)がASSERT等
3と(3と1と2で三値最大)がASSERT等
3と(3と2と3で三値最大)がASSERT等
3と(2と1と3で三値最大)がASSERT等
3と(3と3と2で三値最大)がASSERT等
3と(3と3と3で三値最大)がASSERT等
3と(2と2と3で三値最大)がASSERT等
3と(2と3と1で三値最大)がASSERT等
3と(2と3と2で三値最大)がASSERT等
3と(1と3と2で三値最大)がASSERT等
3と(2と3と3で三値最大)がASSERT等
3と(1と2と3で三値最大)がASSERT等
```

まだ `三値最大` を定義していないため、実行結果は `undefined` となり、テストは失敗します。実際に `gonako run` を実行すると、次のような assertion error になります。

```text
ASSERT失敗: 『3』と『undefined』が一致しません。
```

期待値と実際の値が異なることを確認できたので、最小限の実装に進みます。

### Green: 順に比較する

`src/basic_algorithms.nako3` に、最初の値を最大候補として残りの値と比較する関数を作ります。

```nako3
●(AとBとCで)三値最大
    最大候補 = A
    もし、B > 最大候補ならば
        最大候補 = B
    ここまで
    もし、C > 最大候補ならば
        最大候補 = C
    ここまで
    最大候補を戻す
ここまで
```

実装をテストから呼び出せるように、テストファイルの先頭に次の取り込み命令を追加します。

```nako3
!「../src/basic_algorithms.nako3」を取り込む
```

まず `A` を最大候補とし、`B`、`C` の順に比較して、より大きければ候補を更新します。すべての値を確認し終えた候補が最大値です。`B` や `C` が最大候補と同じ場合に更新しなくても、返す値は変わりません。

テストファイルを実行します。

```bash
cd apps/nadesiko
gonako run test/basic_algorithms_test.nako3
```

### Refactor: 比較対象を明確にする

一時変数 `最大候補` は、比較のたびに「これまでに見た値の最大」を保持します。変数名と更新の順序で意図が読み取れるため、ここでは条件をまとめたり、短い式に置き換えたりせず、このままにします。

## 1.3 3 値の中央値

中央値は、3 つの値を小さい順に並べたときに中央に位置する値です。同じ値がある場合も含めて、分岐ごとの結果をテストします。

### Red: テストを先に書く

```nako3
2と(3と2と1で三値中央値)がASSERT等
2と(3と2と2で三値中央値)がASSERT等
2と(3と1と2で三値中央値)がASSERT等
3と(3と2と3で三値中央値)がASSERT等
2と(2と1と3で三値中央値)がASSERT等
3と(3と3と2で三値中央値)がASSERT等
3と(3と3と3で三値中央値)がASSERT等
2と(2と2と3で三値中央値)がASSERT等
2と(2と3と1で三値中央値)がASSERT等
2と(2と3と2で三値中央値)がASSERT等
2と(1と3と2で三値中央値)がASSERT等
3と(2と3と3で三値中央値)がASSERT等
2と(1と2と3で三値中央値)がASSERT等
```

最大値と異なり、中央値は値の並びによって真ん中となる値が変わります。並び順と同値のケースをテストに含め、条件分岐の抜けを防ぎます。

### Green: 条件を分けて実装する

```nako3
●(AとBとCで)三値中央値
    もし、A >= Bならば
        もし、B >= Cならば
            Bを戻す
        違えば
            もし、A <= Cならば
                Aを戻す
            違えば
                Cを戻す
            ここまで
        ここまで
    違えば
        もし、A > Cならば
            Aを戻す
        違えば
            もし、B > Cならば
                Cを戻す
            違えば
                Bを戻す
            ここまで
        ここまで
    ここまで
ここまで
```

最初に `A` と `B` を比較し、その結果に応じて `C` と比較します。各分岐がどの値を中央値として返すかは、対応するテストで確かめます。条件式の境界には `>=` と `<=` を使い、値が等しい場合も漏れなく扱います。

### Refactor: 条件とテストを対応させる

中央値の実装は分岐が多いため、変更するときはテストを実行してから進めます。条件を入れ替えたり統合したりする場合も、13 のテストが異なる並びと同値のケースを網羅していることを確認します。

## 1.4 条件判定と分岐

数が正、負、ゼロのどれかを判定します。3 つの分類は重複せず、整数の入力をすべて網羅します。

### Red: テストを先に書く

```nako3
「正」と(17を符号判定)がASSERT等
負数 = 0 - 5
「負」と(負数を符号判定)がASSERT等
「ゼロ」と(0を符号判定)がASSERT等
```

### Green: 条件を順に判定する

```nako3
●(Nを)符号判定
    もし、N > 0ならば
        「正」を戻す
    違えば、もし、N < 0ならば
        「負」を戻す
    違えば
        「ゼロ」を戻す
    ここまで
ここまで
```

正と負の条件に当てはまらない整数はゼロです。このように条件を順に分けることで、最後の分岐がどの値を扱うかも明確になります。

## 1.5 繰り返し処理

繰り返しを使って、1 から `N` までの整数の合計を計算します。合計を更新する変数は、繰り返しに入る前に `0` で初期化します。

### Red: テストを先に書く

```nako3
15と(5まで範囲合計)がASSERT等
1と(1まで範囲合計)がASSERT等
0と(0まで範囲合計)がASSERT等
```

### Green: 範囲を繰り返す

```nako3
●(Nまで)範囲合計
    合計値 = 0
    Iを1からNまで繰り返す
        合計値 = 合計値 + I
    ここまで
    合計値を戻す
ここまで
```

`Iを1からNまで繰り返す` は、`I` を 1 から `N` まで変化させながらブロックを実行します。`N` が 0 の場合は 1 から 0 までの反復がなく、初期値の 0 が戻ります。

### 記号を交互に並べる

繰り返しの中で条件を判定し、偶数番目と奇数番目で追加する文字を切り替えます。

```nako3
●(Nを)交互記号作成
    記号一覧 = []
    Iを1からNまで繰り返す
        もし、I % 2 = 1ならば
            記号一覧に「+」を配列追加
        違えば
            記号一覧に「-」を配列追加
        ここまで
    ここまで
    記号一覧を「」で配列結合して戻す
ここまで
```

```nako3
「+-+-+-+-+-+-」と(12を交互記号作成)がASSERT等
「+-+-+」と(5を交互記号作成)がASSERT等
```

ここでは、1 文字ずつ配列に追加してから空文字で結合します。配列への追加は元の配列を変更する操作です。後の章では、配列の変更とコピーの扱いを詳しく学びます。

### 長方形の辺の組み合わせ

面積 `N` の長方形について、辺の長さが整数になる組み合わせを列挙します。同じ長方形を縦横逆にして重複させないため、`I × I` が面積を超えない範囲だけを調べます。

```nako3
●(Nを)長方形辺一覧
    組合せ = []
    Iを1からNまで繰り返す
        もし、I * I <= Nならば
            もし、N % I = 0ならば
                組合せに「{I}x{N / I}」を配列追加
            ここまで
        ここまで
    ここまで
    組合せを「 」で配列結合して戻す
ここまで
```

```nako3
「1x32 2x16 4x8」と(32を長方形辺一覧)がASSERT等
```

外側の繰り返しは `1` から `N` まで進みますが、条件 `I × I ≦ N` が成り立つ候補だけを調べます。`N % I = 0` の場合に限り、`I` と `N / I` を辺の組み合わせに加えます。

## 1.6 多重ループ

九九の表のように、各行と各列の組み合わせを処理するときは、繰り返しの中にもう一つの繰り返しを置きます。外側が行、内側が列です。

### Red: 行と列の数をテストする

```nako3
9と(九九表作成の配列要素数)がASSERT等
```

### Green: 行ごとの配列を作る

```nako3
●九九表作成
    表データ = []
    Iを1から9まで繰り返す
        行データ = []
        Jを1から9まで繰り返す
            行データに(I * J)を配列追加
        ここまで
        表データに行データを配列追加
    ここまで
    表データを戻す
ここまで
```

外側の繰り返しごとに空の `行データ` を作り、内側の繰り返しで積を追加します。行ができたら `表データ` に追加します。結果は 9 個の行を持つ二次元配列です。

### 直角三角形の行を作る

文字列を指定回数繰り返す命令 `リフレイン` を使い、各行の `*` の数を増やします。

```nako3
●(Nを)三角形行作成
    行一覧 = []
    Iを1からNまで繰り返す
        行一覧に(「*」をIでリフレイン)を配列追加
    ここまで
    行一覧を戻す
ここまで
```

```nako3
5と(5を三角形行作成の配列要素数)がASSERT等
```

この関数は表示ではなく、行ごとの文字列を配列で返します。計算と表示を分けると、期待する結果をテストしやすくなります。

## 1.7 テストの実行

テストと実装をそれぞれファイルに保存したら、テストファイルを実行します。`ASSERT等` に失敗がある場合は、`gonako` がエラーを報告します。

```bash
cd apps/nadesiko
gonako run test/basic_algorithms_test.nako3
```

実装例は `gonako` 3.8.8 で構文と期待値を確認しています。記事のコードを編集した場合は、変更後のファイルを再実行して結果を確かめてください。

## まとめ

この章では、次の基本的なアルゴリズムをテストで確かめました。

| アルゴリズム | 学んだこと |
|-------------|-----------|
| 3 値の最大値 | 候補を保持して順に比較する |
| 3 値の中央値 | 並び順と同値を考慮して分岐する |
| 符号判定 | 条件を順に評価し、入力を分類する |
| 1 から N までの合計 | 合計値を初期化し、範囲を繰り返す |
| 交互記号 | 繰り返しと剰余で処理を切り替える |
| 長方形の辺 | 条件で候補を絞り、因数の組を求める |
| 九九の表 | 二重ループで二次元配列を作る |
| 三角形の行 | 繰り返し回数に応じた文字列を作る |

TDD では、テストが例示する振る舞いを少しずつ増やし、実装をその期待に合わせます。次章では配列の操作を取り上げ、要素の追加や探索、並べ替えを扱います。
