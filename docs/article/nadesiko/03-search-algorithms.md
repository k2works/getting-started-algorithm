# 第 3 章 探索アルゴリズム

## はじめに

配列や表から目的の値を見つける処理を探索といいます。この章では、データが未整列でも使える線形探索、整列済み配列を効率よく調べる二分探索、ハッシュ値で探索先を絞る連鎖法を実装します。

探索アルゴリズムの選択には、データの並び、要素数、追加や削除の頻度が関係します。各方法の前提条件と計算量を、境界値を含むテストで確認します。

## 3.1 線形探索

線形探索は、配列の先頭から要素をひとつずつ調べます。配列が整列されていなくても使え、同じ値が複数ある場合は最初に見つかった位置を返します。見つからない場合は `-1` を返します。

### Red: 通常値と境界値をテストする

`test/search_algorithms_test.nako3` に、重複値、先頭、未発見、空配列、文字列のテストを追加します。

```nako3
値一覧 = [6, 4, 3, 2, 1, 2, 8]
「線形探索: 先にある重複値」と(値一覧と2で線形探索)と3で検証
「線形探索: 先頭」と([6, 4, 3]と6で線形探索)と0で検証
「線形探索: 未発見」と([1, 2, 3]と99で線形探索)と(-1)で検証
「線形探索: 空配列」と([]と99で線形探索)と(-1)で検証
「線形探索: 文字列」と([「DTS」, 「AAC」, 「FLAC」]と「DTS」で線形探索)と0で検証
```

### Green: 先頭から順に比較する

`src/search_algorithms.nako3` に関数を定義します。

```nako3
●(値一覧とキーで)線形探索
    配列長 = 値一覧の配列要素数
    Iを0から(配列長 - 1)まで繰り返す
        値 = 値一覧のIを配列参照
        もし、値 = キーならば
            Iを戻す
        ここまで
    ここまで
    (-1)を戻す
ここまで
```

配列長 `n` に対し、最初の要素が一致すれば比較は 1 回、見つからなければ `n` 回です。時間計算量は最良 O(1)、最悪 O(n)、追加の空間計算量は O(1) です。

### 番兵法

番兵法では、探索対象を複製して末尾にキーを追加します。キーは必ず見つかるため、ループ内で配列末尾かどうかを毎回判定せずに済みます。元の配列を変えないこともテストで確かめます。

```nako3
「番兵探索: 発見」と(値一覧と2で番兵探索)と3で検証
「番兵探索: 未発見」と([1, 2, 3]と99で番兵探索)と(-1)で検証
「番兵探索: 空配列」と([]と99で番兵探索)と(-1)で検証
```

```nako3
●(値一覧とキーで)番兵探索
    作業配列 = 値一覧を配列複製
    配列長 = 作業配列の配列要素数
    作業配列にキーを配列追加
    I = 0
    作業配列のIを配列参照 ≠ キーの間
        I = I + 1
    ここまで
    もし、I = 配列長ならば
        (-1)を戻す
    ここまで
    Iを戻す
ここまで
```

番兵に到達したインデックスが元の配列長と同じなら、元配列にはキーがありません。比較回数は線形探索と同じ O(n) です。配列の複製に O(n) の追加領域を使うため、ループ内の判定を減らす代わりにメモリを使います。この教材の実装では、複製コストを含めた効率改善を主張せず、番兵による終了判定の考え方を示します。

## 3.2 二分探索

二分探索は中央の要素とキーを比較し、探索範囲を半分ずつ狭めます。**配列が昇順に整列されていること**が前提です。未整列の配列に使うと、存在するキーを見逃すことがあります。

### Red: 境界と未発見をテストする

```nako3
整列済み = [1, 2, 3, 5, 7, 8, 9]
「二分探索: 中央」と(整列済みと5で二分探索)と3で検証
「二分探索: 先頭」と(整列済みと1で二分探索)と0で検証
「二分探索: 末尾」と(整列済みと9で二分探索)と6で検証
「二分探索: 未発見」と(整列済みと4で二分探索)と(-1)で検証
「二分探索: 空配列」と([]と4で二分探索)と(-1)で検証
「二分探索: 1要素」と([4]と4で二分探索)と0で検証
```

### Green: 範囲を半分ずつ絞る

```nako3
●(整列済みとキーで)二分探索
    左 = 0
    右 = 整列済みの配列要素数 - 1
    左 ≦ 右の間
        中央 = (左 + 右) ÷ 2
        値 = 整列済みの中央を配列参照
        もし、値 = キーならば
            中央を戻す
        違えば、もし、値 < キーならば
            左 = 中央 + 1
        違えば
            右 = 中央 - 1
        ここまで
    ここまで
    (-1)を戻す
ここまで
```

`左` と `右` は、まだキーが存在する可能性のある範囲の両端です。中央の値がキーより小さければ左半分を捨て、大きければ右半分を捨てます。`左 > 右` になると候補がなく、キーは見つかりません。

探索範囲は反復のたびに半分になるため、時間計算量は最悪 O(log n)、追加の空間計算量は O(1) です。100 万件でも、およそ `log₂(1,000,000) ≈ 20` 回の比較で済みます。一方、配列の整列にかかる時間はこの探索の計算量に含みません。

重複した値がある場合、この実装が返すのは見つかった位置のひとつであり、最初の位置とは限りません。最初の重複位置が必要なら、見つかった後も左側の範囲を調べる仕様に変更し、その振る舞いを別のテストで定義します。

## 3.3 ハッシュ法 — 連鎖法

ハッシュ法は、キーからハッシュ値を計算し、格納先の位置を決める方法です。異なるキーが同じ位置になることを**衝突**といいます。連鎖法では、各位置にキーと値の組を配列で保持し、同じ位置に入る要素をひとつのチェインに追加します。

この章の実装は、容量が正の整数、キーが 0 以上の整数であることを前提とします。ハッシュ位置は `キー % 容量` です。探索結果に `-1` を使うため、値として `-1` は格納しません。

### Red: 衝突・重複・削除をテストする

容量 13 の表では、キー 1 と 14 はどちらも位置 1 になります。

```nako3
ハッシュ表 = 13で連鎖ハッシュ作成
追加結果 = ハッシュ表と1と「赤尾」で連鎖ハッシュ追加
「ハッシュ追加: 1」と(追加結果)と(はい)で検証
追加結果 = ハッシュ表と14と「神崎」で連鎖ハッシュ追加
「ハッシュ追加: 衝突」と(追加結果)と(はい)で検証
「ハッシュ探索: 1」と(ハッシュ表と1で連鎖ハッシュ探索)と「赤尾」で検証
「ハッシュ探索: 衝突した14」と(ハッシュ表と14で連鎖ハッシュ探索)と「神崎」で検証
「ハッシュ探索: 未発見」と(ハッシュ表と100で連鎖ハッシュ探索)と(-1)で検証
```

### Green: バケットを配列で作成する

容量分の空バケットを作ります。各バケットは独立した配列で、衝突したキーと値のペアを格納します。

```nako3
●(容量で)連鎖ハッシュ作成
    ハッシュ表 = []
    Iを1から容量まで繰り返す
        ハッシュ表に[]を配列追加
    ここまで
    ハッシュ表を戻す
ここまで
```

### バケットを探索する

```nako3
●(ハッシュ表とキーで)連鎖ハッシュ探索
    容量 = ハッシュ表の配列要素数
    位置 = キー % 容量
    チェイン = ハッシュ表の位置を配列参照
    配列長 = チェインの配列要素数
    J = 0
    J < 配列長の間
        エントリ = チェインのJを配列参照
        保存キー = エントリの0を配列参照
        もし、保存キー = キーならば
            エントリの1を配列参照して戻す
        ここまで
        J = J + 1
    ここまで
    (-1)を戻す
ここまで
```

### 追加・重複拒否・削除

追加前に同じキーがないか確認します。重複キーは上書きせず、`いいえ` を返します。削除では一致した要素をチェインから取り除きます。

```nako3
●(ハッシュ表とキーと値で)連鎖ハッシュ追加
    容量 = ハッシュ表の配列要素数
    位置 = キー % 容量
    チェイン = ハッシュ表の位置を配列参照
    配列長 = チェインの配列要素数
    J = 0
    J < 配列長の間
        エントリ = チェインのJを配列参照
        保存キー = エントリの0を配列参照
        もし、保存キー = キーならば
            いいえを戻す
        ここまで
        J = J + 1
    ここまで
    チェインに[キー, 値]を配列追加
    はいを戻す
ここまで

●(ハッシュ表とキーで)連鎖ハッシュ削除
    容量 = ハッシュ表の配列要素数
    位置 = キー % 容量
    チェイン = ハッシュ表の位置を配列参照
    配列長 = チェインの配列要素数
    J = 0
    J < 配列長の間
        エントリ = チェインのJを配列参照
        保存キー = エントリの0を配列参照
        もし、保存キー = キーならば
            チェインのJを配列削除
            はいを戻す
        ここまで
        J = J + 1
    ここまで
    いいえを戻す
ここまで
```

平均的なバケット長が小さければ、探索・追加・削除は平均 O(1) です。すべてのキーが同じ位置に衝突すると、チェインを先頭から調べるため最悪 O(n) になります。ハッシュ表とチェインが使う追加領域は O(n + m) です（`n` は格納要素数、`m` はバケット数）。

## 3.4 探索方法の比較

| 方法 | 前提条件 | 平均時間 | 最悪時間 | 追加領域 |
|------|---------|---------:|---------:|---------:|
| 線形探索 | なし | O(n) | O(n) | O(1) |
| 番兵探索 | 配列を複製できる | O(n) | O(n) | O(n) |
| 二分探索 | 昇順に整列済み | O(log n) | O(log n) | O(1) |
| ハッシュ連鎖法 | 有効な容量・キー | O(1) | O(n) | O(n + m) |

データが未整列で少量なら線形探索、整列済みで繰り返し探索するなら二分探索が適しています。高速な検索・追加・削除を頻繁に行う場合はハッシュ法が候補になりますが、衝突に備える必要があります。二分探索を使うためだけに毎回整列するなら、整列コストも含めて比較してください。

## まとめ

線形探索は整列を必要とせず、二分探索は整列済み配列を対数時間で調べます。ハッシュ連鎖法はハッシュ位置を使って候補を限定しますが、衝突が多い場合は性能が低下します。探索アルゴリズムは計算量だけでなく、データの前提条件と更新の頻度に合わせて選びます。
