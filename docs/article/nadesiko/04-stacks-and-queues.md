# 第 4 章 スタックとキュー

## はじめに

スタックとキューは、要素を追加する順序と取り出す順序を制御するデータ構造です。この章では、スタックをなでしこ3 の配列で実装し、2 つのスタックを組み合わせてキューを作ります。

どちらも配列を使いますが、スタックは後入れ先出し、キューは先入れ先出しです。境界条件を含むテストで、取り出し順序と空のときの振る舞いを確認します。

## 4.1 スタック

スタックは **LIFO（Last In, First Out：後入れ先出し）** のデータ構造です。皿を積み重ねるように、最後に追加した要素を最初に取り出します。

基本操作は、要素を追加する **プッシュ**、最後の要素を取り出す **ポップ**、最後の要素を取り出さずに参照する **ピーク** です。

### Red: 期待する振る舞いをテストする

空のスタックからのポップやピークは、値がないことを返す仕様にします。操作結果を `[成功したか, 値]` の配列で返すことで、`-1` のような値も通常のデータとして扱えます。空の場合は `[いいえ, 0]` を返し、値の位置は無視します。

```nako3
スタック = スタック作成
「初期状態は空」と(スタックがスタック空)と(はい)で検証

スタックと「first」でスタックプッシュ
スタックと「second」でスタックプッシュ
ピーク結果 = スタックをスタックピーク
「ピークの成功」と(ピーク結果の0を配列参照)と(はい)で検証
「ピークは最後に追加した値」と(ピーク結果の1を配列参照)と「second」で検証
「ピークしても要素は残る」と(スタックがスタック空)と(いいえ)で検証

取出結果 = スタックをスタックポップ
「ポップの成功」と(取出結果の0を配列参照)と(はい)で検証
「LIFO: 後から追加した値」と(取出結果の1を配列参照)と「second」で検証
取出結果 = スタックをスタックポップ
「LIFO: 先に追加した値」と(取出結果の1を配列参照)と「first」で検証
ピーク結果 = スタックをスタックピーク
「空のスタックからのピーク」と(ピーク結果の0を配列参照)と(いいえ)で検証
取出結果 = スタックをスタックポップ
「空のスタックからのポップ」と(取出結果の0を配列参照)と(いいえ)で検証
```

### Green: 配列の末尾で操作する

`src/stack_queue.nako3` にスタックの操作を定義します。配列末尾への追加と取り出しを使うため、先頭要素を動かす必要がありません。

```nako3
●スタック作成
    []を戻す
ここまで

●(スタックと値で)スタックプッシュ
    スタックに値を配列追加
    はいを戻す
ここまで

●(スタックを)スタックポップ
    もし、(スタックがスタック空)ならば
        戻る値 = [いいえ, 0]
        戻る値を戻す
    ここまで
    値 = スタックの配列ポップ
    戻る値 = [はい, 値]
    戻る値を戻す
ここまで

●(スタックを)スタックピーク
    もし、(スタックがスタック空)ならば
        戻る値 = [いいえ, 0]
        戻る値を戻す
    ここまで
    末尾 = スタックの配列要素数 - 1
    値 = スタックの末尾を配列参照
    戻る値 = [はい, 値]
    戻る値を戻す
ここまで

●(スタックが)スタック空
    配列長 = スタックの配列要素数
    (配列長 = 0)を戻す
ここまで
```

なでしこ3 の配列は参照型です。プッシュやポップで受け取った配列を更新すると、呼び出し側の配列にも変更が反映されます。空かどうかを調べる関数は配列の要素数だけを読み、配列を変更しません。

ポップとピークは O(1)、動的配列へのプッシュは容量拡張を含めて償却 O(1) です。スタックが使う領域は格納要素数に比例して O(n) です。

## 4.2 キュー

キューは **FIFO（First In, First Out：先入れ先出し）** のデータ構造です。行列のように、先に追加した要素から順に取り出します。末尾に追加する操作を **エンキュー**、先頭から取り出す操作を **デキュー** と呼びます。

### Red: 追加と取り出しの順をテストする

キューにも空の状態を調べるテストを加えます。要素を取り出す間に新しい要素を追加するテストでは、追加済みの要素が新しい要素より先に返ることも確認します。

```nako3
キュー = キュー作成
「初期状態は空」と(キューがキュー空)と(はい)で検証
取出結果 = キューをキューデキュー
「空のキューからのデキュー」と(取出結果の0を配列参照)と(いいえ)で検証

キューと1でキューエンキュー
キューと2でキューエンキュー
キューと3でキューエンキュー
取出結果 = キューをキューデキュー
「デキューの成功」と(取出結果の0を配列参照)と(はい)で検証
「FIFO: 最初に追加した値」と(取出結果の1を配列参照)と1で検証
キューと4でキューエンキュー
取出結果 = キューをキューデキュー
「FIFO: 2番目に追加した値」と(取出結果の1を配列参照)と2で検証
取出結果 = キューをキューデキュー
「FIFO: 3番目に追加した値」と(取出結果の1を配列参照)と3で検証
取出結果 = キューをキューデキュー
「FIFO: 後から追加した値」と(取出結果の1を配列参照)と4で検証
「すべて取り出すと空」と(キューがキュー空)と(はい)で検証
```

### Green: 2 つのスタックを使う

配列の先頭から要素を削除する単純なキューでは、残りの要素を詰め直す必要があり、デキューが O(n) になります。ここでは、追加用と取り出し用の 2 つのスタックを使います。

```nako3
●キュー作成
    [[], []]を戻す
ここまで

●(キューと値で)キューエンキュー
    入力スタック = キューの0を配列参照
    入力スタックに値を配列追加
    はいを戻す
ここまで

●(キューを)キューデキュー
    出力スタック = キューの1を配列参照
    出力数 = 出力スタックの配列要素数
    もし、出力数 = 0ならば
        入力スタック = キューの0を配列参照
        入力数 = 入力スタックの配列要素数
        入力数 > 0の間
            値 = 入力スタックの配列ポップ
            出力スタックに値を配列追加
            入力数 = 入力数 - 1
        ここまで
    ここまで
    出力数 = 出力スタックの配列要素数
    もし、出力数 = 0ならば
        戻る値 = [いいえ, 0]
        戻る値を戻す
    ここまで
    値 = 出力スタックの配列ポップ
    戻る値 = [はい, 値]
    戻る値を戻す
ここまで

●(キューが)キュー空
    入力スタック = キューの0を配列参照
    出力スタック = キューの1を配列参照
    入力数 = 入力スタックの配列要素数
    出力数 = 出力スタックの配列要素数
    配列長 = 入力数 + 出力数
    (配列長 = 0)を戻す
ここまで
```

キューの内部状態 `[入力スタック, 出力スタック]` のうち、エンキューは入力スタックに追加します。デキュー時に出力スタックが空なら、入力スタックの要素をすべてポップして出力スタックへ移します。この反転によって、最も古い要素が出力スタックの末尾に来ます。

エンキューは償却 O(1) です。デキューは、出力スタックが空で要素を移すときに O(n) かかることがありますが、各要素は入力スタックから出力スタックへ一度だけ移動します。そのため、操作列全体で考えたデキューの償却計算量は O(1) です。2 つのスタックが使う領域は O(n) です。

## 4.3 操作の比較

| データ構造 | 追加 | 取り出し | 取り出し順 | 主な用途 |
|-----------|------|---------|-----------|---------|
| スタック | 償却 O(1) | O(1) | LIFO | 関数呼び出し、深さ優先探索 |
| 2 スタックのキュー | 償却 O(1) | 償却 O(1) | FIFO | タスク処理、幅優先探索 |

どちらも配列の末尾操作を基本にしています。データ構造の違いは、末尾に追加した要素をどの順序で取り出すかです。スタックは最後に追加した要素を先に処理し、キューは最初に追加した要素を先に処理します。

## まとめ

スタックは LIFO、キューは FIFO の規則で要素を取り出します。スタックは配列末尾の追加・取り出しで実装でき、キューは 2 つのスタックを使うと、要素を詰め直さずに償却 O(1) で操作できます。空のときの操作結果も仕様として定め、テストで確かめました。
