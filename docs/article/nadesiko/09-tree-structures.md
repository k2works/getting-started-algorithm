# 第 9 章 木構造

## はじめに

リストでは要素を順番にリンクしました。この章では、ノードを親子関係でつなぐ木構造を学びます。二分探索木は、キーの大小によって探索先を左か右に絞り、ヒープは最小値をすばやく取り出せる完全二分木です。

なでしこ3 ではノードを辞書、子ノードとの関係をノード配列の添字で表現します。木が空であることや探索結果は、通常の値と混同しないよう真偽値と値の組で返します。

この章で扱うものは次のとおりです。

1. 二分木と二分探索木の性質。
2. 二分探索木の追加、探索、削除、中順・前順・後順走査。
3. 配列で表す最小ヒープの追加と最小値の取り出し。

## 9.1 二分木と二分探索木

木はノードとノード間の辺で構成されます。最上位のノードを根、子を持たないノードを葉と呼びます。二分木では、各ノードが持つ子は左と右の最大 2 つです。

二分探索木は、すべてのノードで次の条件を保つ二分木です。

- 左部分木にあるキーは、そのノードのキーより小さい。
- 右部分木にあるキーは、そのノードのキーより大きい。
- この章では、同じキーの追加を拒否する。

たとえば `[5, 3, 7, 1, 4, 6, 8]` の順に追加すると、根は `5`、その左の子は `3`、右の子は `7` になります。二分探索木の中順走査（左部分木、ノード、右部分木）は、キーを昇順に返します。

## 9.2 Red: 二分探索木の振る舞いをテストする

テストでは、追加・探索・重複キーに加え、走査順と削除後も探索木の順序が保たれることを確認します。削除は対象ノードの子の数によって処理が異なります。

```nako3
!「./helper.nako3」を取り込む
!「../src/tree_structures.nako3」を取り込む

木 = 二分探索木作成
値一覧 = [5, 3, 7, 1, 4, 6, 8]
Iを0から(値一覧の配列要素数 - 1)まで繰り返す
    値 = 値一覧のIを配列参照
    木と値で二分探索木追加
ここまで

検索結果 = 木と4で二分探索木探索
「値を探索」と(検索結果の0を配列参照)と(はい)で検証
「探索した値」と(検索結果の1を配列参照)と4で検証
「中順走査は昇順」と((木の二分探索木中順走査)を「,」で配列結合)と「1,3,4,5,6,7,8」で検証
「重複キーを拒否」と(木と4で二分探索木追加)と(いいえ)で検証

「葉を削除」と(木と1で二分探索木削除)と(はい)で検証
「削除後の順序」と((木の二分探索木中順走査)を「,」で配列結合)と「3,4,5,6,7,8」で検証
```

実際のテスト `apps/nadesiko/test/tree_structures_test.nako3` では、空の木、未発見のキー、葉・子が 1 つ・子が 2 つのノード、根の削除も確かめます。削除対象が 2 つの子を持つ場合は、左部分木の最大キーで対象を置き換えます。その最大ノードに左の子がある場合も、親ノードにつなぎ直す必要があります。

## 9.3 Green: 辞書ノードを追加・探索する

木はノード配列、根のノード番号、要素数を持つ辞書です。空の子や根は `-1` で表します。各ノード辞書にはキーと左右の子の番号を格納します。

```nako3
●二分探索木作成
    木 = {"nodes": [], "root": -1, "size": 0}
    木を戻す
ここまで

●(キーで)二分探索木ノード作成
    {"key": キー, "left": -1, "right": -1}を戻す
ここまで
```

追加では、根から比較を繰り返し、キーが小さければ左、大きければ右へ進みます。空いている子の位置で新しいノードを追加します。同じキーを見つけたら追加せず、`いいえ` を返します。探索も同じ比較で進み、見つかったかどうかとキーを `[見つかったか, キー]` で返します。

```nako3
●(木とキーで)二分探索木探索
    ノード一覧 = 木["nodes"]
    現在ノードID = 木["root"]
    現在ノードID ≠ -1の間
        現在ノード = ノード一覧の現在ノードIDを配列参照
        もし、キー = 現在ノード["key"]ならば
            戻る値 = [はい, 現在ノード["key"]]
            戻る値を戻す
        違えば、もし、キー < 現在ノード["key"]ならば
            現在ノードID = 現在ノード["left"]
        違えば
            現在ノードID = 現在ノード["right"]
        ここまで
    ここまで
    戻る値 = [いいえ, 0]
    戻る値を戻す
ここまで
```

ノード数を `n`、木の高さを `h` とすると、探索と追加は O(h) です。木の左右が概ね均等なら高さは O(log n) ですが、昇順など偏った順序で追加すると高さは O(n) になり、操作も O(n) になります。この実装は自動で木の高さを調整しません。

## 9.4 二分探索木からノードを削除する

削除対象を見つけた後は、子の状態ごとに接続を更新します。

1. **葉**: 親の該当する子リンクを `-1` にする。
2. **子が 1 つ**: 親のリンクを唯一の子へつなぎ替える。
3. **子が 2 つ**: 左部分木の最大ノード（中順の直前ノード）のキーで対象を置き換え、そのノードを左の子で置き換える。

対象が根なら、親ではなく木の `root` を更新します。次の抜粋は、2 つの子を持つノードに対する処理です。

```nako3
        先行ノード親ID = 対象ノードID
        先行ノードID = 対象ノード["left"]
        先行ノード = ノード一覧の先行ノードIDを配列参照
        先行ノード["right"] ≠ -1の間
            先行ノード親ID = 先行ノードID
            先行ノードID = 先行ノード["right"]
            先行ノード = ノード一覧の先行ノードIDを配列参照
        ここまで
        対象ノード["key"] = 先行ノード["key"]
        もし、先行ノード親ID = 対象ノードIDならば
            対象ノード["left"] = 先行ノード["left"]
        違えば
            先行ノード親 = ノード一覧の先行ノード親IDを配列参照
            先行ノード親["right"] = 先行ノード["left"]
        ここまで
```

左部分木を右へ進んで最大ノードを探します。最大ノード自身には右の子がありませんが、左の子を持つことはあります。その左の子を切り離された位置へ接続するのが、削除後も木の性質を保つポイントです。

実装は削除済みノードを配列から取り除かず、リンクから到達できない状態にします。したがって、`size` は現在のノード数を示しますが、ノード配列の領域は過去に追加したノード数に比例します。ノード番号を安定させる単純な表現であり、長期間の追加・削除を繰り返す場合には空きノードの再利用などが必要です。

## 9.5 木を走査する

走査では、ノードの左右の子番号を再帰的にたどります。再帰関数は空のノード番号 `-1` に到達したら戻ります。

| 走査 | 処理順 | 主な用途 |
|---|---|---|
| 前順 | ノード、左、右 | 木の構造を出力・複製する |
| 中順 | 左、ノード、右 | 二分探索木から昇順のキーを得る |
| 後順 | 左、右、ノード | 子を処理してから親を処理する |

中順走査では、結果配列を再帰関数に渡し、左部分木の後に自身のキーを追加してから右部分木へ進みます。

```nako3
●(木とノードIDと結果で)二分探索木中順追加
    もし、ノードID = -1ならば
        結果を戻す
    ここまで
    ノード一覧 = 木["nodes"]
    ノード = ノード一覧のノードIDを配列参照
    木とノード["left"]と結果で二分探索木中順追加
    結果にノード["key"]を配列追加
    木とノード["right"]と結果で二分探索木中順追加
    結果を戻す
ここまで
```

どの走査も全ノードを一度ずつ処理するため O(n) 時間です。再帰呼び出しに必要な領域は木の高さに比例して O(h) です。深く偏った木では再帰の呼び出しも深くなるため、実運用では木の平衡化や反復走査を検討します。

最小キーは根から左端、最大キーは根から右端までたどります。木が空の場合は `[いいえ, 0]`、値がある場合は `[はい, キー]` を返します。これにより、キー `0` も通常の値として扱えます。

## 9.6 最小ヒープ

最小ヒープは、親の値がどちらの子の値以下である完全二分木です。根には常に最小値があります。完全二分木は配列で表現でき、添字 `i` の子の位置は `2i + 1` と `2i + 2` です。親の位置は `floor((i - 1) / 2)` です。

なでしこ3 の `/` と `÷` は整数の切り捨てではなく、小数になる場合があります。そのため、親位置を計算するときは `i - 1` から偶数でない余りを取り除いてから 2 で割ります。

```nako3
●(ヒープに値を)最小ヒープ追加
    値一覧 = ヒープ["values"]
    値一覧に値を配列追加
    子位置 = 値一覧の配列要素数 - 1
    整列中 = はい
    子位置 > 0かつ整列中の間
        親候補 = 子位置 - 1
        親位置 = (親候補 - (親候補 % 2)) ÷ 2
        親値 = 値一覧の親位置を配列参照
        子値 = 値一覧の子位置を配列参照
        もし、親値 ≦ 子値ならば
            整列中 = いいえ
        違えば
            値一覧の親位置と子位置を配列入替
            子位置 = 親位置
        ここまで
    ここまで
    はいを戻す
ここまで
```

追加した値を親と比較し、親より小さければ交換して上へ移動します。親子関係が保たれた位置に達するまで繰り返します。高さは O(log n) なので追加時間も O(log n) です。

取り出しでは根を保存し、末尾要素を根と交換して配列から末尾を削除します。その後、親を小さい方の子と交換しながら下へ移動します。要素が 0 件なら `[いいえ, 0]` を返し、値があるときは `[はい, 最小値]` を返します。

```nako3
●(ヒープを)最小ヒープ取り出し
    値一覧 = ヒープ["values"]
    ヒープ要素数 = 値一覧の配列要素数
    もし、ヒープ要素数 = 0ならば
        戻る値 = [いいえ, 0]
        戻る値を戻す
    ここまで
    取り出す値 = 値一覧の0を配列参照
    もし、ヒープ要素数 = 1ならば
        値一覧の配列ポップ
        戻る値 = [はい, 取り出す値]
        戻る値を戻す
    ここまで
    値一覧の0と(ヒープ要素数 - 1)を配列入替
    値一覧の配列ポップ
    親位置 = 0
    整列中 = はい
    値一覧の配列要素数 > 1かつ整列中の間
        左位置 = 親位置 × 2 + 1
        右位置 = 左位置 + 1
        最小位置 = 親位置
        もし、左位置 < 値一覧の配列要素数ならば
            親値 = 値一覧の最小位置を配列参照
            左値 = 値一覧の左位置を配列参照
            もし、左値 < 親値ならば
                最小位置 = 左位置
            ここまで
        ここまで
        もし、右位置 < 値一覧の配列要素数ならば
            最小値候補 = 値一覧の最小位置を配列参照
            右値 = 値一覧の右位置を配列参照
            もし、右値 < 最小値候補ならば
                最小位置 = 右位置
            ここまで
        ここまで
        もし、最小位置 = 親位置ならば
            整列中 = いいえ
        違えば
            値一覧の親位置と最小位置を配列入替
            親位置 = 最小位置
        ここまで
    ここまで
    戻る値 = [はい, 取り出す値]
    戻る値を戻す
ここまで
```

左右の子があるかどうかを配列の要素数と比較してから参照します。片方の子だけがある場合も、存在する子と正しく比較できます。追加・最小値の取り出しはいずれも O(log n)、先頭の参照は O(1) です。

### 二分探索木とヒープの計算量

| 操作 | 二分探索木（平均） | 二分探索木（最悪） | 最小ヒープ |
|---|---:|---:|---:|
| 探索 | O(log n) | O(n) | O(n) |
| 追加 | O(log n) | O(n) | O(log n) |
| 最小値の参照 | O(log n) | O(n) | O(1) |
| 最小値の取り出し | O(log n) | O(n) | O(log n) |
| 任意キーの削除 | O(log n) | O(n) | O(n) |
| 全件走査 | O(n) | O(n) | O(n) |

二分探索木の平均計算量は、木が十分に偏っていない場合の目安です。この実装は自己平衡化しないため、最悪では線形時間です。ヒープは最小値の取り出しに適していますが、任意のキーを探して削除する操作は高速ではありません。必要な操作に合わせてデータ構造を選びます。

## まとめ

二分探索木はキーの大小を使い、探索先を左か右に絞ります。中順走査はキーを昇順で返し、削除では子の数に応じてリンクをつなぎ替えます。木が偏ると操作時間が O(n) になることも確認しました。

最小ヒープは配列で完全二分木を表し、親子の大小関係を保ちながら追加と最小値の取り出しを O(log n) で行います。辞書ノードのリンク、添字計算、空状態の表現をテストで確かめることが、木構造を安全に扱う鍵です。
