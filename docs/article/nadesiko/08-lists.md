# 第 8 章 リスト

## はじめに

配列は添字で要素に直接アクセスできます。一方、リストはノードをリンクでつなぎ、順番にたどるデータ構造です。この章では、単方向の線形リストと、番兵ノードを使う循環双方向リストをテスト駆動で実装します。

なでしこ3 にはクラスやポインタを使わず、ノードを辞書で表します。ノード同士のリンクは、ノードを格納した配列の添字で表現します。添字はリスト内でノードを識別する番号であり、配列のメモリアドレスではありません。ノードの生成やリンク更新を関数に閉じ込め、辞書のキーを直接操作する範囲を狭めます。

この章で扱うものは次のとおりです。

1. 単方向リストで先頭・末尾の追加、探索、先頭・末尾の削除を行う。
2. 番兵ノード付きの循環双方向リストで両端への追加と、ノード番号を指定した削除を行う。
3. 配列との操作時間の違いと、リンクを保つための不変条件を確認する。

## 8.1 線形リストを作る

### Red: 振る舞いをテストする

空のリストへ要素を追加し、順序とサイズを確認します。探索は先頭から順に調べ、見つかった位置を返します。削除結果は `[成功したか, 値]` の配列にし、空リストからの削除をデータ値と区別します。

```nako3
!「./helper.nako3」を取り込む
!「../src/linked_list.nako3」を取り込む

線形リスト = 線形リスト作成
「初期状態は空」と(線形リストが線形リスト空)と(はい)で検証

線形リストと10で線形リスト先頭追加
線形リストと20で線形リスト末尾追加
線形リストと5で線形リスト先頭追加
「追加後の順序」と((線形リストの線形リスト値一覧)を「,」で配列結合)と「5,10,20」で検証
「値を探索」と(線形リストと10で線形リスト探索)と1で検証
「未発見」と(線形リストと99で線形リスト探索)と(-1)で検証
```

実際のテスト `apps/nadesiko/test/linked_list_test.nako3` では、末尾削除、1 要素の削除、空状態、`-1` を値として格納する場合も確かめます。終了値に `-1` を使っていても、削除の成功・失敗は別の真偽値で表すため、`-1` を通常のデータとして扱えます。

### Green: 辞書ノードをリンクする

線形リストは、先頭ノードの番号とノード配列、サイズを持つ辞書です。ノードにはデータと次ノードの番号を格納します。次ノードが存在しないことは `-1` で表します。

```nako3
●線形リスト作成
    リスト = {"nodes": [], "head": -1, "size": 0}
    リストを戻す
ここまで

●(値と次ノードで)線形リストノード作成
    {"data": 値, "next": 次ノード}を戻す
ここまで

●(リストと値で)線形リスト先頭追加
    ノード一覧 = リスト["nodes"]
    ノードID = ノード一覧の配列要素数
    次ノード = リスト["head"]
    ノード = 値と次ノードで線形リストノード作成
    ノード一覧にノードを配列追加
    リスト["head"] = ノードID
    リスト["size"] = リスト["size"] + 1
    ノードIDを戻す
ここまで
```

先頭追加では、新しいノードの `next` に元の先頭番号を保存してから、リストの `head` を新しい番号に更新します。順序を逆にして先頭を上書きすると、元のリストへのリンクを失います。先頭追加は O(1) です。

末尾追加は、先頭から `next` をたどり、次ノードが `-1` のノードのリンクを更新します。末尾番号を別に保持していないため O(n) です。探索と末尾削除も先頭から走査するため O(n)、先頭削除は O(1) です。走査時にたどるリンクの本数は、必ずリストのサイズを超えません。

## 8.2 番兵ノード付き循環双方向リスト

単方向リストでは、末尾のリンクが `-1` で終わり、最後の要素を削除するにはその直前のノードを探します。双方向リストは各ノードが前後の番号を持つため、ノード番号が分かれば、そのノードを O(1) で削除できます。

空リストや両端の境界条件を単純にするため、番号 `0` を番兵ノードとして予約します。番兵の `next` と `prev` は、空リストではどちらも自身の `0` を指します。要素がある場合、番兵から先頭、末尾へと循環してつながります。

### Red: 循環と双方向リンクをテストする

要素の並びを前後両方向から確認し、先頭・末尾ノードの削除後にもリンクが保たれていることを確認します。同じノードを二度削除できないこともテストします。

```nako3
双方向リスト = 双方向リスト作成
中央ノード = 双方向リストと「中央」で双方向リスト末尾追加
先頭ノード = 双方向リストと「先頭」で双方向リスト先頭追加
末尾ノード = 双方向リストと「末尾」で双方向リスト末尾追加

「前方向」と((双方向リストの双方向リスト値一覧)を「,」で配列結合)と「先頭,中央,末尾」で検証
「後方向」と((双方向リストの双方向リスト逆順値一覧)を「,」で配列結合)と「末尾,中央,先頭」で検証
「ノードを削除」と(双方向リストと先頭ノードで双方向リスト削除)と(はい)で検証
「二度目の削除を拒否」と(双方向リストと先頭ノードで双方向リスト削除)と(いいえ)で検証
```

### Green: 隣り合うリンクを更新する

番兵を含むノード配列とサイズを持つ辞書を作成します。各要素ノードには `data`、`prev`、`next`、`active` を格納します。削除済みのノード番号を誤って再利用しないよう、ノード記録は配列に残し、`active` を `いいえ` にします。

```nako3
●双方向リスト作成
    番兵 = {"data": 0, "prev": 0, "next": 0, "active": はい}
    リスト = {"nodes": [番兵], "size": 0}
    リストを戻す
ここまで

●(値と前ノードと次ノードで)双方向リストノード作成
    {"data": 値, "prev": 前ノード, "next": 次ノード, "active": はい}を戻す
ここまで

●(リストと値と前ノードと次ノードで)双方向リスト挿入
    ノード一覧 = リスト["nodes"]
    ノードID = ノード一覧の配列要素数
    ノード = 値と前ノードと次ノードで双方向リストノード作成
    ノード一覧にノードを配列追加
    前ノード = ノード一覧の前ノードを配列参照
    次ノード = ノード一覧の次ノードを配列参照
    前ノード["next"] = ノードID
    次ノード["prev"] = ノードID
    リスト["size"] = リスト["size"] + 1
    ノードIDを戻す
ここまで
```

挿入では、新しいノードを前後のノードの間につなぎ、両隣のリンクを更新します。削除でも同様に、前ノードの `next` と次ノードの `prev` を互いに結び直します。両方を更新することが双方向リストの不変条件です。

```nako3
●(リストとノードIDで)双方向リスト削除
    ノード一覧 = リスト["nodes"]
    ノード数 = ノード一覧の配列要素数
    もし、ノードID < 1またはノードID >= ノード数ならば
        いいえを戻す
    ここまで
    ノード = ノード一覧のノードIDを配列参照
    もし、ノード["active"] = いいえならば
        いいえを戻す
    ここまで
    前ノード = ノード一覧の(ノード["prev"])を配列参照
    次ノード = ノード一覧の(ノード["next"])を配列参照
    前ノード["next"] = ノード["next"]
    次ノード["prev"] = ノード["prev"]
    ノード["active"] = いいえ
    リスト["size"] = リスト["size"] - 1
    はいを戻す
ここまで
```

先頭と末尾の追加は番兵のリンクを使うため、どちらも O(1) です。先頭・末尾の削除も番兵から対象ノードを得て隣接するリンクを更新するため O(1)、指定したノード番号の削除も O(1) です。探索と前後方向への走査は O(n) です。

この実装はノード番号を安定させるため、削除済みノードを `nodes` 配列から取り除きません。したがって、使用領域は現在の要素数ではなく、これまでに追加したノード数に比例します。実用上は、空きノードの再利用や別のノード管理方法を検討できます。

## 8.3 配列とリストを使い分ける

| 操作 | 配列 | 単方向線形リスト | 循環双方向リスト |
|---|---:|---:|---:|
| 添字によるアクセス | O(1) | O(n) | O(n) |
| 先頭への追加・削除 | O(n) | O(1) | O(1) |
| 末尾への追加 | O(1) 償却 | O(n) | O(1) |
| 末尾の削除 | O(1)（末尾削除） | O(n) | O(1) |
| 既知ノードの削除 | O(n) | O(n) | O(1) |

配列は位置を使ったアクセスに向き、リストはリンク先が分かっている位置の追加・削除に向きます。今回のなでしこ3 の実装では、辞書ノードを配列に格納し、その番号でリンクしています。これはポインタを直接扱うのではなく、配列をノード置き場として使う表現です。

## 8.4 テストを実行する

リストの空状態、境界要素、順序、削除、双方向走査を含むテストを実行します。

```bash
cd apps/nadesiko
gonako run test/linked_list_test.nako3
```

すべての章の lint、整形確認、テストは次のコマンドで実行します。

```bash
make check
```

## まとめ

単方向線形リストは、各ノードが次ノードだけを持つため、先頭追加や先頭削除を O(1) で行えます。番兵ノード付きの循環双方向リストは、前後リンクを保つことで両端の操作や既知ノードの削除を O(1) にできます。

なでしこ3 では辞書ノードのキーと更新を関数にまとめ、ノード番号でリンクを表現しました。実装を選ぶときは、必要な操作の計算量だけでなく、リンクの更新責務や削除後のノード管理も考慮します。
