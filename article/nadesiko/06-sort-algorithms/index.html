    第 6 章 ソートアルゴリズム¶

    はじめに¶

    前章では再帰アルゴリズムを学びました。この章では、データを昇順に並べ替える 5 種類のソートアルゴリズムを、TDD の Red → Green → Refactor で実装します。

    同じ入力を並べ替える場合でも、アルゴリズムによって比較や交換の方法、必要なメモリ、入力配列を変更するかどうかが異なります。なでしこ3 の配列は参照型なので、配列を直接並べ替える方法と、複製を作って新しい配列を返す方法をテストで区別します。

    6.1 Red: 期待する並び順をテストする¶

    まず、通常の入力、空配列、単一要素、重複値をテストします。バブル・選択・挿入・クイックソートは入力配列自体を更新し、マージソートは元配列を保持して整列結果を返す仕様です。

    バブルソート¶

    隣り合う 2 要素を比較し、左が大きければ交換します。1 回の走査ごとに未整列部分の最大値が末尾へ移るため、次の走査範囲を 1 つずつ縮めます。本実装は早期終了の最適化を行わず、常に二重ループを実行します。

    選択ソート¶

    未整列部分から最小値の位置を探し、その部分の先頭と交換します。各走査で交換する回数は最大 1 回ですが、最小値を探すための比較は入力の並びにかかわらず必要です。

    挿入ソート¶

    左側を整列済み部分として保ち、次の値をその中の正しい位置まで交換しながら移動します。左隣の値が小さいか等しい位置で止まるため、同じ値の順序を保ちます。整列済み、またはほぼ整列済みの入力では比較回数が少なくなります。

    クイックソート¶

    中央の要素を基準値に選び、左右から走査します。基準値より小さい値が左側、大きい値が右側に来るように交換し、分割した 2 つの範囲を再帰的に処理します。基準位置は配列添字として整数になるように計算します。重複値を含む場合も、等しい値を交換して走査位置を進めるため停止します。

    マージソート¶

    配列を左右に分割し、それぞれを再帰的に整列してから、先頭同士を比較して 1 つの配列に統合します。同じ値の場合に左側を先に追加するため、同値要素の順序を保ちます。入口で配列を複製し、結果を新しい配列として返すため、呼び出し元の配列は変更しません。

    6.3 アルゴリズムの特性を比べる¶

    n は配列の要素数です。時間計算量は標準的な比較ソートの特性を示します。バブルソートは早期終了を実装していないため、整列済み入力でも O(n²) です。

    アルゴリズム 最良時間 平均時間 最悪時間 追加領域 安定性 入力配列
    バブルソート O(n²) O(n²) O(n²) O(1) 安定 変更する
    選択ソート O(n²) O(n²) O(n²) O(1) 不安定 変更する
    挿入ソート O(n) O(n²) O(n²) O(1) 安定 変更する
    クイックソート O(n log n) O(n log n) O(n²) 平均 O(log n) の再帰スタック 不安定 変更する
    マージソート O(n log n) O(n log n) O(n log n) O(n) 安定 保持する

    安定とは、同じキーを持つ要素の相対順序が整列後も維持されることです。選択ソートとクイックソートでは離れた要素を交換するため、一般に安定ではありません。今回のテスト対象は数値配列ですが、安定性はレコードなど同じキーを持つデータを扱う場合に重要になります。

    6.4 テストを実行する¶

    プロジェクトルートから、なでしこ3 の lint、整形確認、全テストを実行します。

    cd apps/nadesiko
make check

    ソートのテストだけを実行する場合は、次のコマンドを使います。

    gonako run test/sort_algorithms_test.nako3

    まとめ¶

    バブル・選択・挿入ソートは、比較と交換を使う基本的な方法です。クイックソートは基準値を使った分割統治、マージソートは分割後の統合で効率を高めます。アルゴリズムを選ぶときは、データ量や入力の傾向だけでなく、安定性、追加領域、入力配列を変更してよいかも考慮します。

    次章では、文字列の基本操作と探索・照合を学びます。
