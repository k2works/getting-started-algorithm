    第 7 章 文字列処理¶

    はじめに¶

    前章ではソートアルゴリズムを学びました。この章では、文字列の基本操作と文字列探索を TDD の Red → Green → Refactor で実装します。

    なでしこ3 の 文字列分解 は文字列を一文字ずつの配列にします。文字単位の配列にしてから処理するため、探索結果の位置はバイト数ではなく、分解後の配列の添字です。ASCII だけでなく日本語文字列でも位置をテストします。

    この章では文字列の長さ、文字の出現回数、反転、回文判定に加え、力まかせ法、KMP 法、Boyer–Moore 法（不一致文字ルール）を実装します。空パターンは位置 0 として扱います。

    7.1 Red: 文字列の仕様をテストする¶

    通常の検索だけでなく、空パターン、未発見、日本語、パターンが本文より長い場合もテストします。探索関数は最初に一致した位置を返し、見つからない場合は -1 を返します。

    !「./helper.nako3」を取り込む
!「../src/string_processing.nako3」を取り込む

「文字数取得: 日本語」と(「なでしこ3」で文字数取得)と5で検証
「文字列反転: 日本語」と(「なでしこ」で文字列反転)と「こしでな」で検証
「回文判定: 回文」と(「たけやぶやけた」で回文判定)と(はい)で検証
「力まかせ探索: 日本語」と(「なでしこ3」と「しこ」で力まかせ探索)と2で検証
「KMP探索: 接頭辞の再利用」と(「ABABABAC」と「ABABAC」でKMP探索)と2で検証
「Boyer-Moore探索: 不一致文字による移動」と(「HERE IS A SIMPLE EXAMPLE」と「EXAMPLE」でボイヤームーア探索)と17で検証
「探索: 空パターン」と(「ABCDE」と「」でKMP探索)と0で検証

    実際のテスト test/string_processing_test.nako3 では、3 つの探索方法に同じ境界条件を与え、結果を比較しています。探索方法を変更しても契約が変わらないことを確認できます。

    文字の出現回数は O(n) 時間、文字列反転は O(n) 時間で処理します。どちらも文字を配列に分解するため、追加領域は O(n) です。回文判定は反転と比較を行うので O(n) 時間、O(n) 領域になります。

    7.3 力まかせ法で探索する¶

    力まかせ法は、本文の各位置を開始位置としてパターン全体を左から比較します。一文字でも異なれば、次の開始位置から比較をやり直します。シンプルですが、最悪の場合は本文の長さを n、パターンの長さを m として O(n × m) 回程度の比較を行います。

    ●(本文とパターンで)力まかせ探索
    本文文字一覧 = 本文を文字列分解
    パターン文字一覧 = パターンを文字列分解
    本文長 = 本文文字一覧の配列要素数
    パターン長 = パターン文字一覧の配列要素数
    もし、パターン長 = 0ならば
        0を戻す
    ここまで
    開始位置を0から(本文長 - パターン長)まで繰り返す
        パターン位置 = 0
        一致継続 = はい
        パターン位置 < パターン長かつ一致継続の間
            本文位置 = 開始位置 + パターン位置
            本文文字 = 本文文字一覧の本文位置を配列参照
            パターン文字 = パターン文字一覧のパターン位置を配列参照
            もし、本文文字 ≠ パターン文字ならば
                一致継続 = いいえ
            違えば
                パターン位置 = パターン位置 + 1
            ここまで

        もし、パターン位置 = パターン長ならば
            開始位置を戻す
        ここまで
    ここまで
    (-1)を戻す
ここまで

    本文とパターンを先に文字配列に変換しているため、比較位置と返す位置の単位が一致します。パターンが本文より長い場合、開始位置の繰り返し範囲が空になり -1 が返ります。

    7.4 KMP 法で不一致を効率化する¶

    KMP 法は、パターン内で「先頭と末尾が一致する長さ」を失敗表に保存します。不一致が起きても、すでに一致していた部分を使ってパターン側の位置を戻すので、本文側をむやみに先頭から比較し直しません。

    失敗表は、各位置までのパターンで最長の「真の接頭辞かつ接尾辞」の長さを記録します。配列は後ろに追加して作り、既に計算した位置を参照します。

    ●(パターン文字一覧で)KMP失敗表作成
    パターン長 = パターン文字一覧の配列要素数
    失敗表 = []
    もし、パターン長 = 0ならば
        失敗表を戻す
    ここまで
    失敗表に0を配列追加
    Iを1から(パターン長 - 1)まで繰り返す
        一致長 = 失敗表の(I - 1)を配列参照
        前方文字 = パターン文字一覧の一致長を配列参照
        現在文字 = パターン文字一覧のIを配列参照
        一致長 > 0かつ前方文字 ≠ 現在文字の間
            一致長 = 失敗表の(一致長 - 1)を配列参照
            前方文字 = パターン文字一覧の一致長を配列参照
        ここまで
        もし、前方文字 = 現在文字ならば
            一致長 = 一致長 + 1
        ここまで
        失敗表に一致長を配列追加
    ここまで
    失敗表を戻す
ここまで

●(本文とパターンで)KMP探索
    本文文字一覧 = 本文を文字列分解
    パターン文字一覧 = パターンを文字列分解
    本文長 = 本文文字一覧の配列要素数
    パターン長 = パターン文字一覧の配列要素数
    もし、パターン長 = 0ならば
        0を戻す
    ここまで
    失敗表 = パターン文字一覧でKMP失敗表作成
    本文位置 = 0
    パターン位置 = 0
    本文位置 < 本文長の間
        本文文字 = 本文文字一覧の本文位置を配列参照
        パターン文字 = パターン文字一覧のパターン位置を配列参照
        もし、本文文字 = パターン文字ならば
            本文位置 = 本文位置 + 1
            パターン位置 = パターン位置 + 1
            もし、パターン位置 = パターン長ならば
                (本文位置 - パターン長)を戻す
            ここまで
        違えば、もし、パターン位置 > 0ならば
            パターン位置 = 失敗表の(パターン位置 - 1)を配列参照
        違えば
            本文位置 = 本文位置 + 1
        ここまで
    ここまで
    (-1)を戻す
ここまで

    前方文字が一致しなければ失敗表を使って一致長を短くし、同じ本文文字との比較を続けます。本文位置は後戻りしません。前処理と検索を合わせた時間計算量は O(n + m)、失敗表に必要な追加領域は O(m) です。

    7.5 Boyer–Moore 法で右から比較する¶

    Boyer–Moore 法はパターンの末尾から比較し、不一致が起きたときにパターンを右へ移動します。ここでは「不一致文字ルール」を実装します。本文側の不一致文字がパターン内にあれば、その文字の最後の出現位置が不一致位置と重なるようにずらします。パターン内に見つからなければ、1 文字以上進めます。

    ●(本文とパターンで)ボイヤームーア探索
    本文文字一覧 = 本文を文字列分解
    パターン文字一覧 = パターンを文字列分解
    本文長 = 本文文字一覧の配列要素数
    パターン長 = パターン文字一覧の配列要素数
    もし、パターン長 = 0ならば
        0を戻す
    ここまで
    開始位置 = 0
    開始位置 ≦ (本文長 - パターン長)の間
        パターン位置 = パターン長 - 1
        一致継続 = はい
        パターン位置 ≧ 0かつ一致継続の間
            本文位置 = 開始位置 + パターン位置
            本文文字 = 本文文字一覧の本文位置を配列参照
            パターン文字 = パターン文字一覧のパターン位置を配列参照
            もし、本文文字 = パターン文字ならば
                パターン位置 = パターン位置 - 1
            違えば
                一致継続 = いいえ
            ここまで
        ここまで
        もし、パターン位置 < 0ならば
            開始位置を戻す
        ここまで
        不一致本文位置 = 開始位置 + パターン位置
        不一致文字 = 本文文字一覧の不一致本文位置を配列参照
        最終出現位置 = -1
        Iを0から(パターン長 - 1)まで繰り返す
            文字 = パターン文字一覧のIを配列参照
            もし、文字 = 不一致文字ならば
                最終出現位置 = I
            ここまで
        ここまで
        移動量 = パターン位置 - 最終出現位置
        もし、移動量 < 1ならば
            移動量 = 1
        ここまで
        開始位置 = 開始位置 + 移動量
    ここまで
    (-1)を戻す
ここまで

    この実装は不一致文字の最終出現位置を毎回パターン内で探すため、前処理済み表を使う一般的な実装より単純ですが、追加の前処理領域を使いません。比較と位置探索の両方を合わせた最悪時間計算量は O(n × m) です。実際にどれだけ先へ移動できるかは、本文とパターンの文字によって変わります。

    7.6 探索方法を比較する¶

    方法 前処理 最悪時間 追加領域 特徴
    力まかせ法 なし O(n × m) O(n + m) の文字配列 実装が簡潔で、小さな入力に適する
    KMP 法 O(m) O(n + m) O(n + m) の文字配列と O(m) の失敗表 本文位置を後戻りせず、最悪でも線形時間
    Boyer–Moore 法（不一致文字ルール） なし O(n × m) O(n + m) の文字配列 パターン末尾から比較し、文字に応じて移動する

    n は本文の文字数、m はパターンの文字数です。ここでは実装が明確な不一致文字ルールのみを使っています。Boyer–Moore 法のすべての変種や、良い接尾辞ルールを含む実装の計算量と混同しないようにします。

    7.7 テストを実行する¶

    プロジェクトルートから、なでしこ3 の lint、整形確認、すべての章のテストを実行します。

    cd apps/nadesiko
make check

    文字列処理のテストだけを実行する場合は、次のコマンドを使います。

    gonako run test/string_processing_test.nako3

    まとめ¶

    文字列分解 で文字列を文字配列にすると、基本操作と探索を同じ添字の考え方で実装できます。力まかせ法は単純な基準実装になり、KMP 法は失敗表で再比較を減らし、Boyer–Moore 法は末尾から比較して不一致文字に応じて移動します。検索対象の大きさや最悪時間の要件に合わせて方法を選びます。

    次章では、線形リストや連結リストなどのリスト構造を学びます。
